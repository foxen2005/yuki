# Avisos: un banner que mandamos nosotros y se cierra para siempre

**Fecha:** 2026-11-26
**Estado:** pendiente de aprobación

## Qué pide Jean

Poder mandar un aviso a los Yuki ya instalados desde aquí, que salga como banner
en la app, y que **cuando el usuario lo cierre no vuelva a aparecer nunca**. Sin
molestar.

## Sin servidor

No hace falta montar nada. Yuki ya consulta GitHub cada 4 horas para buscar
actualizaciones; el aviso viaja por el mismo camino.

Un archivo `avisos.json` en el repo, leído desde
`https://raw.githubusercontent.com/foxen2005/yuki/master/avisos.json`. Publicar
un aviso = editar ese archivo y hacer commit. Retirarlo = borrarlo del archivo.
Coste cero, historial en git, y si GitHub no contesta no pasa nada: no hay
banner y la app sigue igual.

```json
{
  "avisos": [
    {
      "id": "2026-11-nuevo-pos",
      "desde": "2026-11-26",
      "hasta": "2026-12-20",
      "versionMinima": "0.4.6",
      "titulo": { "es": "…", "en": "…" },
      "texto":  { "es": "…", "en": "…" },
      "boton":  { "es": "Ver más", "en": "Learn more" },
      "enlace": "https://pudutecnologia.cl/…"
    }
  ]
}
```

- **`id`** es lo que se recuerda al cerrarlo. Nunca reciclar un id: cambiarle el
  texto a un id ya cerrado no lo resucita, y así debe ser.
- **`hasta`** hace que un aviso caduque solo. Si alguien abre Yuki en enero, no
  le sale la promoción de diciembre aunque nunca la haya visto ni cerrado.
- **`versionMinima` / `versionMaxima`** para avisar solo a quien corresponde
  («actualiza, tu versión tiene un fallo» no va para los que ya actualizaron).
- Los textos por idioma se enganchan con el plan de idiomas
  (`2026-11-26-idiomas.md`); mientras no exista, se usa `es`.

## Lo que NO se va a poder mandar

Esta es la decisión importante del plan: **el aviso es texto plano, un título,
un cuerpo y como mucho un botón con un enlace**. Nada de HTML, nada de imágenes
remotas, nada de scripts.

Si el banner pintara HTML que viene de internet, cualquiera que llegue a ese
archivo —o a la cuenta de GitHub— estaría ejecutando código dentro de Yuki, con
las sesiones de Gmail y WhatsApp del usuario al lado. No vale la pena por un
banner. El renderer monta el texto con `textContent`, nunca con `innerHTML`, y
el enlace se valida (`https:` y nada más) antes de abrirse **en el navegador del
sistema**, no dentro de Yuki.

## Que no moleste de verdad

- **Uno a la vez.** Si hay varios vigentes, sale el más nuevo y el resto espera.
- **No en el primer arranque.** Nadie quiere publicidad a los diez segundos de
  instalar algo. El primer aviso puede salir a partir del segundo día de uso.
- **Cerrar es para siempre.** El id cerrado se guarda en `userData`, junto a
  `permissions.json` y los demás. No se borra ni al actualizar.
- **Se puede apagar.** Un interruptor en Configuración: «Avisos de Digital Fox».
  Apagado, ni siquiera se descarga el archivo.
- **Sin seguimiento.** La petición es un GET a un archivo estático: no lleva
  identificador, ni versión en la URL, ni nada que permita contar usuarios. El
  filtro por versión lo hace la app en local, no el servidor. Esto importa
  porque Yuki se vende como «tus sesiones son tuyas y no pasan por nadie»; un
  banner no puede ser la grieta de esa promesa.

## Dónde se ve

Reutilizando lo que ya existe, no inventando un componente nuevo: Yuki ya tiene
`#toast-update` (el aviso persistente de «Reiniciar ahora») y
`#google-auth-banner`. El aviso usa ese mismo lenguaje visual, abajo, con su X.

## Archivos

- `src/main/avisos.js` — descarga, caché, filtros por fecha y versión, y el
  registro de cerrados en `userData/avisos-cerrados.json`.
- `src/main/ipc-handlers.js` — `avisos:pendiente` y `avisos:cerrar`.
- `src/renderer/` — el banner y el interruptor en Configuración.
- `avisos.json` en la raíz del repo — el contenido.

## Lo que esto cuesta

- **Yuki empieza a hablar con internet por algo que no es actualizarse.** Hoy
  solo contacta GitHub para buscar versiones. Es defendible, pero es un cambio
  en lo que la app promete, y por eso el interruptor para apagarlo no es
  opcional.
- **Si esto pasa a ser publicidad de terceros y no avisos nuestros**, hay que
  revisar las políticas de la Microsoft Store antes: anuncios de terceros tocan
  la clasificación por edad y las declaraciones de la ficha. Avisos propios
  sobre productos propios es otra cosa. No lo doy por sabido: habría que
  mirarlo el día que se plantee.

## Cierre

- `/code-review` sobre el cambio.
- Probar con un `avisos.json` de prueba antes de publicar el de verdad.
- Release a GitHub cuando Jean apruebe.

## Qué probar

1. Publicar un aviso → aparece en Yuki en el siguiente ciclo (hasta 4 h) o al
   abrir la app.
2. Cerrarlo → no vuelve. Reiniciar Yuki → sigue sin volver.
3. Editar el texto de ese mismo id → sigue sin volver.
4. Un aviso con `hasta` ya pasado → no aparece nunca.
5. Un aviso con `versionMinima` superior a la instalada → no aparece.
6. Apagar los avisos en Configuración → no se descarga nada.
7. Sin internet, o con GitHub caído → la app arranca igual, sin errores.
8. Un aviso con HTML o con un enlace `javascript:` en el JSON → se muestra como
   texto y el enlace no se abre.
